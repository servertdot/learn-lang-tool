# TTS options for Learn Lang Tool

Research date: 2026-07-22. The product is a browser extension whose v1 language pair is `en → ru`; pronunciation of the English selection is the primary use case, with Russian playback as an optional second direction.

## Decision first

**Requirement update:** generated audio must be saved into Anki, so Web Speech is not sufficient as the primary provider. For the current `en → ru` product, assuming the saved pronunciation is the original English selection/context sentence, use an explicitly installed Kokoro English model pack as the local-first implementation. Keep Web Speech only as an instant preview fallback before that pack is installed. If Russian audio must also be saved, use a hosted bilingual provider first; the local Russian model found in this research has a non-commercial license.

The local provider must return encoded audio bytes, not merely play speech. Generate speech in the existing offscreen inference document, encode the waveform as mono MP3 at 24 kHz and 64 kbps, and attach it to the note through AnkiConnect's `audio` member using `data`, `filename`, and destination `fields`. MP3 is the most universally supported audio format across AnkiWeb and mobile clients ([Anki media documentation](https://docs.ankiweb.net/media.html)); AnkiConnect accepts base64 `data` and appends the resulting `[sound:filename]` marker to those fields ([AnkiConnect implementation](https://github.com/FooSoft/anki-connect/blob/master/plugin/__init__.py)).

Do not put base64 audio inside the existing `chrome.storage.local` Anki queue. Queue a synthesis recipe (`text`, language, provider/model revision, voice, speed) and generate during sync, or keep blobs in a separate IndexedDB/Cache API store referenced by ID. Prefer the recipe for the first version; use a deterministic content-hash filename so retries reuse the same media name.

Web Speech and `chrome.tts` play speech but do not return encoded audio bytes, so they cannot directly populate Anki's `[sound:...]` field. Keep preview playback behind a separate interface from the required `AudioTtsProvider` that returns an audio `Blob`.

Transformers.js is a browser inference runtime, not a reason to add an LLM. TTS needs a purpose-built speech model. The currently viable browser-local models each have a material product limitation for this project: Kokoro is attractive and permissively licensed but has no Russian voice; MMS has English and Russian models but is non-commercial; SpeechT5 is relatively large, English-only, and operationally more complex.

## What v1 actually needs

There are two different product capabilities:

1. **Preview playback:** speak the current selection when the user clicks a speaker icon. No persistent file is required.
2. **Exportable audio:** produce stable bytes that can be cached, replayed later, or sent through AnkiConnect.

Keeping these separate avoids paying the model-size, latency, backend, and licensing costs of exportable audio before it is needed.

## Option comparison

| Option | `en` / `ru` | First use / runtime | Offline and privacy | Audio file | Cost | Main constraint |
|---|---|---|---|---|---|---|
| Web Speech `speechSynthesis` | Depends on installed browser/OS voices; discover at runtime | Immediate; no app model | A voice may be local or remote. Require `localService === true` for a strict offline mode | No | Free | Voice availability and quality differ by device |
| `chrome.tts` | Depends on installed Chrome voices | Immediate; adds the `tts` extension permission | Engine-dependent | No | Free | Chromium-specific; little benefit over Web Speech for this UI |
| Kokoro 82M via Transformers.js | Good English; no Russian in the published voice list | About 86 MB mixed-precision or 92.4 MB q8, plus runtime/voice assets | Local after first download and browser cache | Yes | No per-call fee | Not bilingual; model card warns that very short utterances can be weak |
| Meta MMS VITS via Transformers.js | Separate English and Russian checkpoints | 38.4 MB quantized per language, roughly 77 MB for both | Local after first download and browser cache | Yes | No per-call fee | CC BY-NC 4.0 weights; unsuitable if commercial use is possible |
| SpeechT5 via Transformers.js | Published checkpoint is fine-tuned on English LibriTTS | Multiple quantized ONNX graphs total roughly 178 MB and it needs a speaker embedding | Local after downloads/cache | Yes | No per-call fee | Larger and more moving parts than Kokoro/MMS; no Russian checkpoint here |
| Google Cloud TTS | Many English and Russian voices | Network request; backend credential required | Selected text leaves the device; generated bytes can be cached | Yes | Standard: $4 / 1M chars; Neural2: $16 / 1M; Chirp 3 HD: $30 / 1M | Requires backend, billing, and privacy disclosure |
| OpenAI Speech API | English and Russian; built-in voices are optimized for English | Network request/stream; backend credential required | Selected text leaves the device; returns MP3/Opus/AAC/FLAC/WAV/PCM | Yes | `tts-1`: $15 / 1M chars; `tts-1-hd`: $30 / 1M | Requires backend and AI-voice disclosure |

At 100 characters per sentence, character-priced APIs are fractions of a cent: about $0.0004 for Google Standard and $0.0015 for OpenAI `tts-1`, before backend/storage/egress costs. Cost is therefore less important than pronunciation quality, latency, privacy, and credential handling at this product's likely volume.

## Browser and OS speech: recommended v1

The Web Speech specification exposes `speechSynthesis.getVoices()` and marks every voice with a language and `localService` flag. The user agent's default voice can be either a local or remote service, so “uses the OS voice” must not be equated with guaranteed offline processing. The implementation should enumerate voices, choose by exact BCP-47 language, and prefer local voices; a privacy setting can exclude remote voices entirely ([Web Speech API specification](https://webaudio.github.io/web-speech-api/#speechsynthesisvoice)).

The same API supplies play, pause, resume, cancel, rate, pitch, and utterance lifecycle events, but no method that returns PCM or an encoded file ([Web Speech API specification](https://webaudio.github.io/web-speech-api/#tts-section)). This makes it an excellent preview provider and a dead end for Anki audio export.

No manifest permission is needed because this is a web-platform API used from a document context. In this repository, invoke it from the visible content UI or an extension document after the user's click; keep it out of the MV3 service worker, which has no DOM. A small provider interface should hide the platform details:

```ts
interface SpeechPreviewProvider {
  listVoices(language: string): Promise<PreviewVoice[]>;
  speak(text: string, options: { voiceId: string; rate: number }): Promise<void>;
  stop(): void;
}
```

`chrome.tts` is a reasonable Chromium-only fallback. It provides `speak`, voice enumeration, rate/pitch, and events, but requires the non-optional `tts` extension permission and still only plays synthesized speech ([Chrome `tts` API](https://developer.chrome.com/docs/extensions/reference/api/tts), [Chrome permission reference](https://developer.chrome.com/docs/extensions/reference/api/permissions)). It should not be the default while Chrome and Firefox builds share product code.

Acceptance tests for v1 should cover at least Chrome on macOS, Windows, and Linux: available English voices, cold first click, repeated click/cancel, a 1–3 word selection, a sentence, punctuation/numbers, and behavior with only remote or no matching voice. “A voice exists” is not a quality guarantee, so the UX needs a disabled/unavailable state rather than silently speaking with the wrong language.

## Browser-local neural models

Transformers.js runs ONNX models on CPU through WASM by default and can opt into WebGPU. Hugging Face still describes WebGPU as experimental outside broad Chromium support, so a production extension needs a WASM fallback ([Transformers.js overview](https://huggingface.co/docs/transformers.js/en/index), [WebGPU guide](https://huggingface.co/docs/transformers.js/guides/webgpu)). The library can cache model and WASM assets through the browser Cache API; once cached, repeated use can work offline ([Transformers.js environment options](https://huggingface.co/docs/transformers.js/api/env)). For this extension, follow the existing Bergamot pattern: an explicit model-pack install, pinned revision/checksums, progress UI, and no silent download on the first speaker click.

### Kokoro

The official ONNX conversion works with the Transformers.js `text-to-speech` pipeline. The 82M-parameter model is Apache-2.0; published variants are 326 MB fp32, 163 MB fp16, 92.4 MB q8, and 86 MB mixed precision ([Kokoro ONNX model card](https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX)). Its published voices cover American/British English plus Japanese, Mandarin, Spanish, French, Hindi, Italian, and Brazilian Portuguese—not Russian. The same model documentation warns that non-English support can be thin and utterances below 10–20 tokens may be weak, which matters for word/short-phrase learning ([Kokoro voice documentation](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md)).

Kokoro is the best local experiment for high-quality English audio, not the best bilingual default. Revisit it if exportable English audio becomes important and a roughly 90 MB optional pack is acceptable.

### MMS VITS

Meta publishes separate 36.3M-parameter VITS checkpoints for English and Russian. HF's Transformers.js-compatible ONNX conversions include 38.4 MB quantized models for each language and directly return waveform samples ([English ONNX files](https://huggingface.co/Xenova/mms-tts-eng/tree/main/onnx), [Russian ONNX model and example](https://huggingface.co/Xenova/mms-tts-rus), [Russian quantized file](https://huggingface.co/Xenova/mms-tts-rus/blob/main/onnx/model_quantized.onnx)). This is the smallest straightforward bilingual local path found.

However, both base checkpoints use CC BY-NC 4.0 ([English model card](https://huggingface.co/facebook/mms-tts-eng), [Russian model files](https://huggingface.co/facebook/mms-tts-rus/tree/main)). Treat MMS as a technical prototype only unless the project's distribution and monetization are known to comply with that non-commercial license.

### SpeechT5

The published Microsoft checkpoint is MIT-licensed and fine-tuned for TTS on English LibriTTS ([Microsoft SpeechT5 model card](https://huggingface.co/microsoft/speecht5_tts)). The Transformers.js conversion requires an acoustic model, vocoder path, and a speaker embedding; its quantized encoder, merged decoder, and decoder/postnet/vocoder graphs are about 88.4 MB, 71.1 MB, and 18.3 MB respectively ([Transformers.js SpeechT5 usage](https://huggingface.co/Xenova/speecht5_tts), [ONNX file listing](https://huggingface.co/Xenova/speecht5_tts/tree/44e1005e7667656336d469029a2d16f3adfeb46c/onnx)). It has no advantage over Kokoro for this v1 and no Russian coverage in this checkpoint.

## Hosted audio providers

A hosted provider makes sense only for exportable audio or if browser voices fail the quality bar.

Google Cloud is the strongest budget candidate for an `en`/`ru` product: its official catalogue includes multiple `ru-RU` Standard, WaveNet, and Chirp 3 HD voices, as well as extensive English choices ([Google supported voices](https://cloud.google.com/text-to-speech/docs/voices)). Current list pricing is $4 / 1M characters for Standard, $16 / 1M for Neural2, and $30 / 1M for Chirp 3 HD, with free monthly allowances shown on the same page ([Google Cloud TTS pricing](https://cloud.google.com/text-to-speech/pricing)). Run a small blind pronunciation test before choosing a tier; higher price is not by itself evidence of better language-learning pronunciation.

OpenAI's Speech endpoint can stream or return MP3, Opus, AAC, FLAC, WAV, or PCM. Russian is listed as supported, although the built-in voices are optimized for English; OpenAI also requires a clear disclosure that the voice is AI-generated ([OpenAI TTS guide](https://developers.openai.com/api/docs/guides/text-to-speech)). The stable character-priced models are $15 / 1M characters for latency-oriented `tts-1` and $30 / 1M for quality-oriented `tts-1-hd` ([`tts-1`](https://developers.openai.com/api/docs/models/tts-1), [`tts-1-hd`](https://developers.openai.com/api/docs/models/tts-1-hd)).

Neither provider key belongs in the extension. OpenAI explicitly says never to deploy an API key in a browser and to route requests through a backend; Google likewise says client code should send requests to a server that adds credentials ([OpenAI key safety](https://help.openai.com/en/articles/5112595-best-practices-for-api-key), [Google API key practices](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices)). The repository's optional API can become that boundary, but doing so changes TTS from the current zero-infrastructure product path into an opt-in hosted feature.

## Suggested rollout

1. **v1 preview:** add a speaker button backed by Web Speech. Speak the source selection, prefer a local exact-language voice, expose 0.75× / 1× rate, and remember the chosen voice ID per language. No model download and no additional permission.
2. **Instrument quality, not text:** locally record provider/voice ID, requested language, duration, error class, and whether the user replayed; do not collect the sentence.
3. **Define the file boundary now:** keep preview separate from an `AudioTtsProvider.synthesize(): Promise<{ bytes, mimeType }>` so Anki support does not contaminate the simple playback implementation.
4. **If Anki audio is requested:** first benchmark Google Standard/WaveNet and OpenAI `tts-1` on a fixed English/Russian pronunciation set. Cache generated audio by a hash of normalized text + language + provider + voice + rate + provider/model version, with a bounded LRU policy.
5. **If strict offline export is requested:** prototype Kokoro for English. Re-evaluate Russian local models and their licenses at that time; do not ship MMS by default under the current non-commercial license.
